# O17 内存事故与资源保护

用户报告服务器因内存耗尽卡死。主机日志确认 2026-10-06 23:44:37（北京时间）重启，旧 RHFB 进程已不存在。前一启动周期未查到内核 OOM-kill 记录，试验也没有保存峰值；因此不能给出事故峰值或断言内核 OOM killer 执行了终止。

## 已确认的问题

`O17_coordinate_normal_kernel_20261006_attempt02` 的 24 GiB 和 1800 秒只是写入报告、在计算后检查的值，没有限制内存分配。SIGKILL 或服务器重启也不会执行 Python 的 finally。旧报告的 running 状态已更正为 interrupted_server_reboot_results_unavailable；修改前原件保存在资源验证目录。

坐标原型虽分块计算传播核，仍构造完整复坐标密度和完整梯度。P=882 时，每个种类的 R 约 190 MiB，两个种类及其梯度约 760 MiB；这不包括自动微分图、复制和中间场，不能用于证明峰值安全。故障试验未产生新的可信 O17 结果。

## 已实施保护

- 数值入口 `scripts/run_rhfb_limited.py` 使用 systemd 用户服务的真实 cgroup v2：默认最多 4 GiB、swap=0、最多两个 CPU、运行超时。worker 启动前读取内核限制并保存独立证明；不可用时拒绝启动。
- 启动器锁、随 worker/exec 保留的第二把锁，以及存活服务检查共同禁止并行运行；启动器正常中断时终止服务。启动器被 SIGKILL 后，服务仍有内存和超时限制，第二项任务会被拒绝。
- 大于 192 个坐标点或 96 个原始维度的坐标原型在构造密度之前拒绝运行；当前 P=882、D=432 的 O17 入口禁止重启。这是工程隔离，不能通过减少物理空间绕开并冒充成功。
- 新训练入口要求实际 cgroup 限制；原源码、检查点、历史结果及完整归档保留。开发文件修改前后快照与 SHA256 已保存。

## 验证与证据边界

`outputs/validation/memory_safety_20261006/` 保存证据。四项纯文本限额测试通过。1 GiB 真实限额下，入口测试确认 energy_only 和 evaluate 都在首次数组分配前拒绝大空间；没有计算核能量或运行网络训练。

64 MiB 纯等待任务验证：强制终止启动器后，第二项启动被存活服务检查拒绝（`parent_death_single_job.json`）；测试服务随后显式清理。第一版测试脚本因继承管道等待超时而失败，已保留失败记录，修正测试等待方式后通过。这不是计算内存故障。

64 MiB 隔离探针尝试申请 96 MiB，实际结果为服务 timeout，不能写成 oom-kill。MemoryHigh=75% 可能先导致回收阻塞；可确认的是 worker 读取了 memory.max=67108864、swap=0，任务被超时机制终止，未完成超限分配。未记录结束时 memory.events，不能声称已实测 OOM-kill。

成功的 transient unit 可能被 systemd 清理，此后查询显示 LoadState=not-found、MemoryMax=infinity；这些退出后属性不代表执行期间无限制。新的报告使用 worker 在执行前持久保存的 kernel_limit_evidence。结束后 cgroup 已消失时，峰值和事件字段为 null，不能当作零。

后续完整核计算仍需实现真正有界的内存算法，并在资源入口下验证。此次只修复资源保护，不修改 PKA1、D1S、阻塞、无海处方或径向 ADF，也不代表完整奇核求解器验收通过。

## 2026-10-07 本地重计算与保护补充

监督进程现在保留独立锁，读取真实子进程退出码并清理本服务内后代进程；只有退出码、清理、最终 cgroup 限额与内存事件证据完整，才允许 `completed`。旧内核没有 `memory.peak` 时保留 null；定时采样峰值只能给出下界，不能冒充内核峰值。测试额外要求本轮新生成且全部通过的 JUnit 文件，避免 systemd 外部中止后退出码为零被误报测试通过。

超时、子进程异常、缺测试完成文件、外部停止、启动器被强制终止后拒绝并行均已有探针证据。新监督器另外通过 9 项报告判定测试，覆盖缺最终资源记录、OOM 事件增量、缺管理器记录及 GPU 只有监测而没有分配器配额证明的情况。证据位于 `outputs/validation/local_safe_restart_20261007/`。探针初次重跑误读旧报告的错误记录保留，后续探针使用唯一文件名防止混淆；这次错误没有启动核计算。

CUDA 模式要求指定空闲 GPU UUID，同时拒绝已有计算进程。PyTorch caching allocator 的硬配额与实际驱动占用监测分开：默认驱动监测预算 8 GiB，其中预留 512 MiB 给上下文，分配器硬配额 7.5 GiB。第三方 CUDA 分配不属于 PyTorch allocator；驱动监测是反应式停止，不能描述为整块显存的内核硬上限。`verify_cuda_memory_guard.py` 已在真实 GPU 上验证超过 1.5 GiB allocator 配额的 2 GiB 请求被拒绝、complex128 重计算梯度一致；原始证据在 `cuda_guard_proof.json`。随后增加了由配置函数写入监督器独立文件的配额证明，缺证明的 GPU 作业不得被认定成功。当前 GPU 被其他项目占用，保护器已拒绝抢用。

同一 O17 空间（D=432、活动轨道 M=42）的 CPU 重计算固定场 NN 诊断已完成中子和质子各 20 次优化。实际 memory.max=3 GiB、swap.max=0，进程最大 RSS=633.77 MiB，cgroup 定时采样峰值=421.11 MiB；两者统计范围不同。所有 memory.events 终值为零；每个种类 20 次 backward 重计算，训练谱求解与刷新次数为零。报告与检查点保存在 `outputs/validation/O17_m42_cpu_recompute_20261007/`，监督证明及汇总分别为 `O17_nn_cpu_guard.json`、`O17_nn_summary.json`。

这次固定场诊断完整运行，但不是已求得 O17：中子完整对易残差范数从 631.444 降到 628.443 MeV，质子从 617.952 降到 614.952 MeV；最终粒子数误差分别约 −9.26×10⁻⁶ 和 −4.10×10⁻⁶，未达到 10⁻⁶。中子数奇偶性保持 −1、质子保持 +1，阻塞重叠约 0.999991，纯度误差约 10⁻¹³；网络编码器及输出层实际更新。完整自洽场梯度、物理无海分支和空间收敛仍须独立验收，不能用这些工程和代数检查替代。

随后完成的完整 PH 逐通道能量/全原始空间场及二阶梯度验证保持原测试物理通道；独立 oracle 按能量块立即反传后释放图，避免同时保留全遍历图。原二阶测试的六区间网格不能通过原五点径向空间构造要求，测试扩大到七区间；没有缩小 O17 网格。两项验证在 3 GiB 限额下全部通过，进程最大 RSS 1847.23 MiB。修正了 tile 字节估计遗漏 P 因子的错误，缓存仅为固定原始空间采样 O(PD)，没有用训练场更新或替换基底。

新独立 `selfconsistent_stationarity.py` 每次联合重建 PH 正常场及完整 D1S 配对场作用，损失穿过 PH 二阶导数和配对作用，不冻结自洽场。三项检查通过，其中真实小空间显式奇中子阻塞态的 Q/chi 联合方向 AD 与中心差分一致；中子/质子数宇称为 −1/+1，纯度保持。进程最大 RSS 1863.51 MiB、无 OOM 事件。这个接口还不是完整训练器，未认证物理无海分支，也不是 O17 同空间验收。

## O17 原空间完整场闭合与联合训练入口

新的分块原始空间后端已在 O17 的原 D=432、P=882 网格完成核对，没有运行被隔离的稠密坐标原型。实际 3 GiB 硬限额、swap=0，运行 716.18 秒，进程最大 RSS 1648.12 MiB；内存事件均为零，监督器确认真实子进程正常退出和后代清理完成。中子、质子各 186624 个完整正常场矩阵元素的最大差分别为 3.87×10⁻¹²、2.96×10⁻¹² MeV，逐 PH 通道能量最大差 9.09×10⁻¹³ MeV。参考来自已存档的独立 Python 场计算，输入密度及源码 SHA256 一致，没有调用 Fortran，也没有训练谱求解或刷新。

结果保存在 `outputs/validation/O17_streamed_PH_closure_20261007/`；保护证明为 `local_safe_restart_20261007/O17_streamed_PH_guard.json`。这是固定神经网络密度的完整 PH 后端验收，不是 O17 的自洽、无海或空间收敛验收。

新增联合训练器每次重建两种核子的完整 PKA1 和 D1S 场，反传包含 PH Hessian-vector product，试探步也重新计算场；接受前检查粒子数宇称及阻塞重叠，失败回滚，接受后原子保存网络、优化器、化学势及历史。训练全过程禁止谱求解，检查点暂不支持续训，明确标记 `resume_supported=false`。生产泛函路径要求真实 GeneralizedDensityNet，活动轨道数至少 max(40,N+32)。

联合训练编排及有限谱带 BdG 分支原型共 7 项检查已在 3 GiB 硬限额下通过。首次测试仅在对照矩阵的实数/复数类型相乘处失败，原记录保留；修复后独立参考、完整对易残差和纯度检查通过。分支原型只适用于有完整谱带证书的小空间，不能以此认证 O17 无海分支。O17 现存诊断尚缺完整带标签上下界及沿路径间隙证明，见 `O17_BRANCH_EVIDENCE_AUDIT_20261007.md`。

真实 GeneralizedDensityNet 联合训练随后完成了 N=3、Z=2 的小盒集成验证：R=1.4 fm、h=0.2 fm、K=1、D=48、P=108，两个种类各 M=40。两次接受更新、5 次完整场计算、4 次模型反向重计算，损失从 14608.14484 降至 14603.55300；编码器及输出层的参数变化 L2 分别为 1.0233×10⁻⁴ 和 1.6970×10⁻⁴。运行 359.51 秒、进程最大 RSS 2422.36 MiB，实际硬限额仍为 3 GiB、swap=0，内存事件均为零。数据、逐通道能量及版本快照位于 `outputs/validation/joint_real_nn_m40_channels_20261007/`，对应监督证明为 `joint_real_nn_channels_guard.json`。

逐通道输出只在自定义场算子的正向遍历中收集已分离的标量，反向不重复累计；D1S 单独加入一次，总和误差约 4.55×10⁻¹³ MeV。相关 7 项闭合与梯度检查通过。训练入口还拒绝不完整 PH 提供器、同维度不同网格、改动的 PKA1 参数以及 PH 截断与输入不一致的情况，5 项准入/编排检查通过。这些准入修改发生在上述运行之后，未改变默认训练的泛函或梯度算法；运行所用版本保存在开始快照中。

该小盒结果不是 O17：最终粒子数误差约 1.17×10⁻⁵、完整驻定残差仍大，物理无海分支未验收。论文复核另确认当前 PH 的 L=2K 只能视为所选截断，密度依赖与导数核的角向收敛仍需独立检验；见 `PH_MULTIPOLE_CUTOFF_AUDIT_20261007.md`。不会以内部闭合、损失下降或内存保护通过代替完整奇核物理解验收。

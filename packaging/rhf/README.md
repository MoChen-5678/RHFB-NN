# DPL-NN-RHF: no-refresh neural-network relativistic Hartree-Fock (spherical)

This package is a spherical **relativistic Hartree-Fock (RHF)** solver for the
density-dependent PKA1 and PKO2 Lagrangians. It keeps the full Fock terms of
σ, ω, ρ (vector and tensor), π and Coulomb.

- The occupied Dirac spinors are generated by a neural network on a fixed
  radial grid: 0–20 fm with h = 0.1 fm.
- Training minimizes the energy together with the full-space Euler–Lagrange
  residual.
- **No Dirac Hamiltonian is ever diagonalized and the basis is never
  refreshed.** The counters `eigensolve_count` and `refresh_count` in the
  output are zero.
- The Dirac sea is excluded by an inverse-Hamiltonian constraint.

## Validation (PKA1, 300 epochs, versus the Core-1204 Fortran RHF)

| Nucleus | E/A NN (MeV) | E/A Core-1204 (MeV) | ΔE/A (MeV) | Δr_matter (fm) |
|---|---|---|---|---|
| ¹⁶O  | −7.34763 | −7.34895 | +0.0013 | 0.005 |
| ⁴⁰Ca | −8.35015 | −8.33779 | −0.0124 | 0.014 |
| ⁴⁸Ca | −8.49996 | −8.49494 | −0.0050 | 0.018 |

All energies are without the centre-of-mass correction.

## 1. Installation

You need Linux, an NVIDIA driver supporting CUDA 12.1 (driver ≥ 530; CPU
also works but is slow), and conda, mamba, micromamba or python3.10.

```bash
tar xzf dpl-nn-rhf-*.tar.gz && cd dpl-nn-rhf-*
bash install_env.sh            # creates ./env (torch 2.5.1+cu121, numpy 2.2.6, scipy 1.15.3)
```

`install_env.sh` only creates `./env` and `./.pkgs` inside this directory.
It does not modify any other environment.

## 2. Resource protection (required reading)

Every job is started through `scripts/run_rhfb_procguard.py`, which does
the following:

- runs the job in its own session and samples the **resident memory of the
  whole process tree every 0.5 s** and **each card's VRAM every 2 s**;
- **terminates the whole job** if host memory exceeds `HOST_MIB`
  (default 8192 MiB), if any card exceeds `GPU_MIB` (default 8192 MiB), or
  on timeout;
- also sets a **PyTorch allocator hard limit** on every card (`GPU_MIB`
  minus 512 MiB);
- uses **only the physical cards listed in `RHFB_AUTHORIZED_GPUS`**. If the
  variable is unset, it refuses to use any GPU;
- admits a card only if it has at least `GPU_MIB` + 1 GiB of free VRAM,
  so it never squeezes onto a card someone else is using;
- takes one lock per card: jobs that share a card are mutually exclusive,
  while jobs on different cards can run in parallel.

This is sampling-based protection, not a kernel cgroup limit; a very fast
spike can overshoot by about one sampling interval. **Never kill other
users' processes.**

```bash
export RHFB_AUTHORIZED_GPUS=0,1      # cards you may use on this server
```

## 3. Acceptance test (before the first run)

```bash
examples/run_tests.sh          # CPU
examples/run_tests.sh 0,1      # also checks two-card streamed Fock exchange
```

Pass criterion: everything `passed` and `logs/guard_tests.json` shows
`"status": "completed"`.

## 4. Running

```bash
# one nucleus: NAME Z N EPOCHS GPUS [MODEL]
examples/run_one.sh O16  8  8   300 0
examples/run_one.sh Pb208 82 126 300 0,1      # two cards: Fock exchange split per κ pair, memory-bounded
```

### Running in the background, safe against dropped connections

```bash
setsid nohup examples/run_one.sh Ca48 20 28 300 0,1 > logs/Ca48.out 2>&1 < /dev/null &
# parallel lanes (edit the card assignments first):
setsid nohup examples/run_lanes.sh > logs/lanes.out 2>&1 < /dev/null &
```

### Notes

- **Resuming.** Run the same command again. If
  `runs/NAME/training_checkpoint.pt` exists, the run resumes automatically
  (checkpoints every 10 epochs).
- **Two cards (`GPUS=0,1`).** Each κ pair's Fock contribution is computed
  in its own checkpoint, and the pairs are split between the cards. For
  heavy nuclei this cuts the per-card memory peak from "does not fit" to a
  few GB, as measured on T4s with the RHFB code (similar order for RHF):

  | Nucleus | Per-card VRAM peak |
  |---|---|
  | ⁴⁰Ca | 2.3 GB |
  | ¹³²Sn | 3.7 GB |
  | ²⁰⁸Pb | 5.1 GB |

  The streamed result agrees with the single-card result to 10⁻⁸ (see the
  tests).
- **Extra flags.** Use `EXTRA="--graph-offload recompute"` to recompute
  activations on a single card and save memory. `--help` lists all options:
  `env/bin/python -m dpl_rhf.cli.rhf_train --help`.
- **Number of epochs.** The validation used 300 epochs. Heavy nuclei need
  more; check that `stationarity_rms_mev` in `history.csv` is falling
  steadily.

## 5. Output (`runs/NAME/`)

| File | Contents |
|---|---|
| `summary.json` | `energy_total_no_com_mev`, `energy_per_a_no_com_mev`, energy split by channel `energy_terms_mev`, radii and stationarity in `diagnostics`, `solver_counts` (eigensolve/refresh = 0), training configuration |
| `history.csv` | Per-epoch energy, stationarity residual, inverse-Hamiltonian branch score, learning rate, time |
| `best_checkpoint.pt` / `training_checkpoint.pt` | Best state / resumable checkpoint |
| `density_matrix_factors.npz`, `local_observables.npz`, `nonlocal_hamiltonians.npz` | Density-matrix factors, local densities and fields, nonlocal Hamiltonians |

Logs are in `logs/`: `NAME.log` holds the training output and
`guard_NAME.json` the guard record (status, memory peak, per-card VRAM peaks).

## 6. Sending results back

```bash
tar czf results_$(hostname)_$(date +%m%d).tar.gz runs/*/summary.json runs/*/history.csv \
    runs/*/*.npz logs/
```

The large checkpoints (`*.pt`) are only needed if you want to continue
training elsewhere.

## 7. Common problems

| Message | Meaning and fix |
|---|---|
| `No authorized GPU list` | Set `RHFB_AUTHORIZED_GPUS` |
| `unavailable or busy` | Not enough free VRAM on that card; switch cards or wait |
| `Another guarded RHFB job is active on the requested devices` | One of your own jobs already holds that card |
| `host_memory_limit_exceeded` / `gpu_memory_budget_exceeded` | The guard terminated it. Use two cards (`0,1`) or `EXTRA="--graph-offload recompute"`. Raising the limits needs a decision from whoever is responsible for the server |
| Slow (low GPU utilization) | The computation is CPU-bound. Check `uptime`: on a heavily loaded machine our process gets little CPU time |
